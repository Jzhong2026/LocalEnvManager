# 需求文档：项目部署管理功能

## 1. 背景
LocalEnvManager 用于按分类（Category）管理本地项目（Project）并运行其更新/部署流程。当前已实现分类-项目的层级结构与基础执行器，但存在以下问题：
- 项目缺少完整的部署配置字段（目标路径、备份目录）。
- 编辑对话框与项目详情展示不完整，部分绑定属性在模型中未定义，导致详情区域显示空白。
- 缺少"构建完成后将备份目录文件同步到目标路径"的核心能力。

## 2. 目标
完善单个项目的部署配置与执行流程：每个项目根据其部署方式（dotnet publish / dotnet build / PowerShell / uvicorn）正确执行，并在构建成功后把备份目录的文件递归覆盖到目标路径。

## 3. 功能需求
1. 分类（Category）下包含多个项目（Project），层级结构保持不变。
2. 每个项目头部展示：名称（Name）+ 部署方式（Deployment Mode）徽标。
3. 部署方式枚举：`dotnet publish`、`dotnet build`、`PowerShell`、`uvicorn`（可扩展）。
4. 不同部署方式对应不同输入：
   - `dotnet publish` / `dotnet build`：输入 dotnet 命令参数（例如 `publish -c Release -o out`）。
   - `uvicorn`：输入 uvicorn 命令参数（例如 `main:app --host 0.0.0.0 --port 8000`）。
   - `PowerShell`：通过文件选择器选择 `.ps1` 脚本文件。
5. 每个项目需配置：
   - 源路径（Source Path）：项目源码/工作目录（可相对分类基路径）。
   - 目标路径（Target Path）：部署/运行目录。
   - 备份目录（Backup Folder）：构建完成后用于覆盖目标路径的文件来源。
6. 执行流程：运行部署命令 → 命令成功（退出码 0）后，将备份目录下的所有文件（含子目录）递归复制到目标路径，覆盖同名文件；目标路径不存在时自动创建。
7. `uvicorn` 为启动型服务（不等待退出），在启动前完成备份目录同步。

## 4. 非功能需求
- 路径通过文件夹/文件选择器选择，减少手动输入错误。
- 所有中文/英文文案使用系统简体中文字体（微软雅黑），不使用不支持中文的字体。
- 相对路径（源路径、脚本路径、目标路径、备份目录）在解析时以所属分类的 BasePath 为基准。

## 5. 验收标准
- 编辑对话框可配置上述所有字段，且根据部署方式动态显示对应输入（命令输入框 vs 脚本文件选择器）。
- 点击"执行更新"后，对应命令正确运行；成功后目标路径被备份目录内容覆盖。
- 项目详情展开后正确显示：源路径、命令/脚本、备份目录、目标路径。
- 应用启动无 XAML 资源缺失错误，中文字体显示正常。
